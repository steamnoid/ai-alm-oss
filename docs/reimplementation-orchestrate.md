# Re-implementation notes — orchestrate

Kruczki z live implementacji `aialm-oss-orchestrate`. Backend: Jira Cloud REST v3. Wariant I exclusive mutator — jeden krok = jedno legalne przejście `STAGE` (nigdy `BLOCKED` jako stan).

- **Atomic sync kolumny + krotki (usunięty decoupling).** `advanceOne` (`src/aialm/oss/orchestrate/index.ts`) robi **atomowo** `updateState` (custom fields `AIALM STAGE/ROLE/AGENT` + `syncStateLabels`) **+** `transitionIssue` do natywnego statusu kanban. Custom fields są źródłem prawdy; natywna kolumna jest jej mirror. Wcześniejszy decoupling (`native bez zmian`) został usunięty na życzenie — workflow i kolumny są teraz 1:1 ze `STAGE`.
- **`STAGE_NATIVE_STATUS` (`orchestrate/index.ts:66`).** Mapa name-based (odporna na ID statusów między boardami): `IDLE/READY → Backlog`, `AWAITING_AGENT_PICKUP → AWAITS AGENT PICKUP`, `IN_PROGRESS_BY_AGENT → AGENT WORKING`, `AWAITING_HUMAN_APPROVAL → AWAITS HUMAN APPROVAL`, `DONE → Done`. Helper `stageNativeStatus(stage)`. Resolucja transition po `to.name` (case-insensitive), nie po stałym `transitionId` — Jira zwraca `to.name` i `to.id` (stale `name` vs kolumna też się zdarza).
- **Workflow 1:1 ze STAGE (live).** `WELLBEINGT/statuses`: `Backlog(10007) / AWAITS AGENT PICKUP(10214) / AGENT WORKING(10216) / AWAITS HUMAN APPROVAL(10215) / Done(10009)`. Board `182` (`WELLBEINGT board`, kanban): `Backlog→[]`, `Backlog→10007`, `AWAITS AGENT PICKUP→10214`, `AGENT WORKING→10216`, `AWAITS HUMAN APPROVAL→10215`, `Done→10009`. Dostępne transitions z `Backlog`: `AWAITS AGENT PICKUP(2) / AGENT WORKING(3) / AWAITS HUMAN APPROVAL(4) / Backlog(11) / Done(41)`.
- **`getTransitions` / `transitionIssue` (`adapter/jira.ts:438`).** Przywrócone po decouplingu: `GET /rest/api/3/issue/{key}/transitions` → `[{id,name,to:{id,name}}]`, `POST .../transitions {transition:{id}}`. `exactOptionalPropertyTypes` wymaga ostrożnego spreadu `to`.
- **`ROLE=AI` handoff (transient).** Człowiek stawia `ROLE=AI` (przy `STAGE∈{READY,AWAITING_HUMAN_APPROVAL}`, `AGENT=none`) — orchestrator advance → `AWAITING_AGENT_PICKUP/null/aialm-oss-po-analyze` + native `AWAITS AGENT PICKUP` (replace `PO→AI`; `AI` transient). Invariant `ROLE=AI ⇒ AGENT=none` w `shared/state.ts:111`. `inferGate` czyta krotkę z custom fields, nie z labeli.
- **Bramka discover (jedyna zaimplementowana).** `STAGE∈{READY,AWAITING_HUMAN_APPROVAL} + ROLE=AI + AGENT=none + Backlog + hasCandidateApproval` → `PICKUP_OK` (`READY/AWAITING_HUMAN_APPROVAL → AWAITING_AGENT_PICKUP`). Inny `ROLE` → `NOT_CANDIDATE`. `isInBacklog` case-insensitive. `hasCandidateApproval` — ludzka `✅/👍` lub `approve/LGTM/looks good` w komentarzu (reakcje AI nie liczą się; `isAiMarked` rozróżnia AI proposal comments).
- **Atomic rollback.** Snapshot `prevLabels + prevNative status` przed mutacją; `didTransition` flag. Na błędzie po `updateState` (np. brak transition) → revert `updateState(prev) + reverse transitionIssue(prevNative) + setLabels(prevLabels)` (best-effort) — nigdy częściowa mutacja. Brak docelowego transition → `ERROR` (`brak natywnego transition do '...'`).
- **Idempotencja.** Re-run po pickupie (krotka już `AWAITING_AGENT_PICKUP/—/po-analyze`) → `NOT_CANDIDATE` (bez podwójnej mutacji). `NOT_CANDIDATE` także gdy `STAGE∉{READY,AWAITING_HUMAN_APPROVAL}` lub `ROLE≠AI`.
- **Governance flaga DEBUG (`shared/state.ts:164`).** Label per-ticket `aialm:debug:on/off` (brak obu = `on`). `isDebugOn`, `syncStateLabels` zachowuje `aialm:debug:*`. Gdy `on`, **każda** czynność orchestratora logowana jako `[AI-generated] Orchestrate — <KEY> — DEBUG: <result> — <detail>\n\nStan: <status> | <state>` na tickecie (`logDebugForRow`). Gdy `off`, tylko legacy `BLOCKED:`.
